# Лекторий: семантический поиск по видеолекциям

Веб-сервис для студентов и преподавателей. Можно загрузить видеолекцию файлом или ссылкой, найти нужный момент по смыслу запроса и перейти к нему по таймкоду. Конспект, оглавление и ключевые термины строятся автоматически.

## Возможности

- Загрузка MP4/WebM или импорт по ссылке (YouTube, Vimeo, прямая ссылка), прогресс обработки по этапам.
- Распознавание речи с таймкодами, субтитры в плеере, текст лекции синхронно с видео: клик по фразе перематывает видео.
- Поиск по смыслу по одной лекции, курсу или всем лекциям сразу. В выдаче кадр из видео, фрагмент текста, таймкод и переход к моменту.
- Тепловая карта: на шкале лекции видно, где именно говорят о найденном.
- Закладки с заметками на моментах видео (клавиша B), отдельная страница со всеми закладками, «Продолжить просмотр» на главной.
- Автоконспект, оглавление с разделами и подразделами, главы на шкале под плеером.
- Ключевые термины подсвечиваются в тексте, при наведении показывается определение, видны все упоминания.
- Вопрос-ответ по лекции со ссылками на моменты видео.
- «Поделиться моментом» (ссылка на секунду видео), экспорт конспекта в Markdown и на печать / PDF.
- Настройки: тема, размер субтитров, скорость, автопрокрутка, подсветка терминов, сведения о моделях, горячие клавиши.
- Работает без интернета: все модели локальные.

Вход и регистрация по email и паролю (JWT). Загружать файлы, удалять лекции и создавать курсы можно только после входа. Лекции и курсы личные: их видит только тот, кто добавил (аккаунт или, без входа, этот браузер), включая видео, обложки и субтитры. Лекции, загруженные до этого, общие: их видят все, но изменить или удалить их нельзя. Закладки, заметки и история просмотра хранятся на сервере: после входа они принадлежат аккаунту, без входа привязаны к анонимному id браузера (заголовок `X-Client-Id`). Настройки интерфейса хранятся только в браузере.

## Запуск целиком

Нужен Docker с Compose v2.20+ и около 15 ГБ места.

### Скачать архив llama-cpp-python
### 1. Создай папку для моделей

```bash
mkdir -p ml-service/models
cd ml-service/models
```

Он нужен для сборки `llama-cpp-python` из исходников (без AVX-512, чтобы работало на любом CPU).

```powershell
curl.exe -L -o ml-service/llama_cpp_python-0.3.1.tar.gz "https://files.pythonhosted.org/packages/b5/14/85052d76d7f92ed97de7a7bc54f6b6cc04c2c25f6d8775cfe37d976e1842/llama_cpp_python-0.3.1.tar.gz"
```

Linux/MacOS
```bash
curl -L -o ml-service/llama_cpp_python-0.3.1.tar.gz "https://files.pythonhosted.org/packages/b5/14/85052d76d7f92ed97de7a7bc54f6b6cc04c2c25f6d8775cfe37d976e1842/llama_cpp_python-0.3.1.tar.gz"
```

```bash
docker compose up --build
```

- Интерфейс: http://localhost:8080
- API: http://localhost:8000/api/v1

Модели (Whisper, e5, Qwen) скачиваются при первом обращении, поэтому первая загруженная лекция обрабатывается дольше. После этого интернет не нужен. Всё работает на CPU: распознавание занимает примерно половину длительности видео или больше, конспект строится по частям уже после статуса `ready`.

Если интерфейс открывают не с этой же машины, задайте адрес API, который видит браузер: `PUBLIC_URL=http://<ip>:8000 docker compose up --build`.

Токены входа подписываются ключом `JWT_SECRET`, по умолчанию `dev-secret-change-me`. Не для демо на своей машине - задать свой: `JWT_SECRET=<длинная случайная строка> docker compose up --build`.

## Telegram-бот

Бот [@poisklkbot](https://t.me/poisklkbot) - второй клиент того же API: поиск, вопросы по лекциям, конспект, оглавление, термины, импорт по ссылке и закладки.

Аккаунт сайта можно привязать к Telegram: Настройки → «Привязать Telegram» открывает бота, он подтверждает привязку, и закладки в боте и на сайте становятся общими (прежние закладки из бота переходят в аккаунт). Статус и отвязка в боте - `/account`. Бот ходит в API с общим секретом `BOT_SECRET` (по умолчанию `dev-bot-secret-change-me`, compose передаёт его и API, и боту; для запуска без Docker - в `bot/.env`).

В `docker compose up` он запускается сам, если в `bot/.env` задан `BOT_TOKEN` (образец - `bot/.env.example`). Ссылки на моменты ведут на `FRONT_URL`, по умолчанию http://localhost:8080, и открываются в Telegram Desktop на той же машине.

Отдельно, без Docker:

```bash
cd bot && pip install -r requirements.txt && python -m bot
```

## Запуск фронтенда отдельно

Нужен Node.js 20+.

```bash
cd frontend
npm install
npm run dev            # http://localhost:5173
```

По умолчанию фронт работает на встроенном моке: данные хранятся в браузере, загружены две демо-лекции. Так интерфейс можно показать без бэкенда.

С бэкендом (он слушает `http://localhost:8000`):

```bash
VITE_API_URL=http://localhost:8000/api/v1 npm run dev
```

Сборка: `npm run build`, результат в `frontend/dist`. Адрес API задаётся на этапе сборки той же переменной `VITE_API_URL`, без неё собирается версия с моком.

## Запуск бэкенда отдельно

`docker compose up --build` в каталоге `backend/`: база, миграции, API на :8000 и ML-сервис на :8001.

## Для разработчиков

- `openapi.yaml` - единый источник правды по API. После изменения контракта: `npm run gen:api` во `frontend/`.
- `frontend/src/api/` - клиент: `httpApi.ts` (настоящий бэкенд), `mockApi.ts` и `mockData.ts` (мок).
- `frontend/scripts/demo-video.sh` - генерирует видео для демо-лекций мока в `frontend/public/demo/` (нужен ffmpeg).
