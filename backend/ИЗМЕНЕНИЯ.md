# Что поменяно в бэке перед защитой

Запуск всего проекта (фронт + API + ML + база) из корня архива:

```bash
docker compose up --build
```

Интерфейс http://localhost:8080, API http://localhost:8000/api/v1. Если фронт открывают с другой машины: `PUBLIC_URL=http://<ip>:8000 docker compose up --build`.

Модели качаются при первом обращении (Whisper turbo, e5, Qwen GGUF в `ml-service/models/`), первая лекция обрабатывается дольше. Уже скачанный `qwen2.5-3b-instruct-q4_k_m.gguf` можно просто положить в `ml-service/models/`.

## Исправления

- `GET /lectures` отдавал каждую лекцию дважды (цикл был продублирован).
- `GET /courses` на пустой базе отдавал `null` вместо `[]`.
- `playback.url` и `thumbnail_url` теперь абсолютные (`PUBLIC_URL`), иначе фронт на другом порту не находил видео.
- Обложки реально генерируются (`extractThumbnail` раньше не вызывался).
- `/search` учитывает `lecture_id`, `course_id`, `limit`, отдаёт 404 на чужой `lecture_id`, считает `highlights` (совпадения слов со словоформами, UTF-16). Поиск идёт точным перебором: HNSW с WHERE мог вернуть меньше строк, чем LIMIT.
- `/ask` учитывает `course_id`, история обрезается до 20 реплик.
- Конспект: раньше весь транскрипт шёл в Qwen с `n_ctx=4096` и падал на лекциях длиннее ~10 минут. Теперь по частям (~5 мин раздел, не больше 12): название, краткое содержание, подтемы, термины; затем общий конспект из этих частей. Таймкоды терминов ищутся по тексту, термины без упоминаний отбрасываются. `n_ctx=8192`.
- Whisper `large-v3` заменён на `large-v3-turbo` (переменная `ASR_MODEL`), faster-whisper 1.1.1. Таймаут запросов к ML поднят до 4 ч: длинная лекция на CPU не укладывалась в 10 минут.
- ML Dockerfile ставит `llama-cpp-python==0.3.1` из PyPI: архива `llama_cpp_python-0.3.1.tar.gz` в репозитории не было. Сборка с `GGML_NATIVE=ON`: со старыми флагами (AVX2/FMA/F16C выключены) конспект 5-минутного видео шёл 28 минут, с нативными 4 минуты.
- `av==13.1.0` закреплён: faster-whisper 1.1.1 падает на свежем PyAV (`open() got an unexpected keyword argument 'metadata_errors'`), распознавание не работало вообще.
- yt-dlp: `-f mp4` на YouTube выбирал видео без звука, дальше падало извлечение звука. Теперь `bv*+ba/b`, до 720p, h264. Свежему yt-dlp для YouTube нужен JS-рантайм: в образ добавлен `nodejs` и `yt-dlp[default]`.
- В `error` больше не попадает весь вывод ffmpeg/yt-dlp, только последняя строка; при видео без звука - понятный текст.
- Вывод LLM чистится от иероглифов и пустых пунктов (Qwen 3B иногда их вставляет). Лекция от 3 минут делится минимум на 3 раздела.
- Длительность пишется сразу после извлечения звука (ffprobe), wav удаляется после распознавания.
- `language` из формы загрузки и импорта передаётся в Whisper.
- Импорт: `source` = `youtube`/`vimeo`/`url` по адресу, название по умолчанию берётся с площадки (yt-dlp), ссылка проверяется.
- `PATCH /lectures/{id}` без `course_id` больше не убирает лекцию из курса; `null` убирает.
- `POST /retry` при упавшем только конспекте перезапускает только конспект. Текст ошибки конспекта пишется в `error`.
- Слишком большой файл - 413 `file_too_large`; при ошибке сохранения запись лекции удаляется.
- CORS пускает любой origin (собранный фронт живёт на :8080).
- `/data` в контейнере создаётся с владельцем `api`, видео лежат в именованном томе `media`: с bind mount на Linux бэк не мог писать.

## Как проверено

Всё поднято нативно (Postgres 18 + pgvector 0.8.7, тот же Python 3.12 и пакеты, что в образах) и прогнано на настоящей лекции с YouTube (5 мин, русский):

- импорт по ссылке: скачивание, название с площадки, обложка, длительность; распознавание 3.5 мин на CPU, язык `ru`;
- поиск своими словами: нужный фрагмент первым, 0.1-0.4 с, подсветка словоформ; фильтры по лекции и курсу, 404/422;
- конспект: 3 раздела с подразделами, 4 термина с таймкодами, 4 минуты; `/ask` с историей 35-45 с;
- закладки и прогресс по `X-Client-Id`, удаление лекции, retry после падения;
- фронт в браузере: видео по абсолютному URL, `?t=` перематывает, субтитры, поиск.

Docker-образы целиком на моей машине не собирались (нет docker) - если что-то не встанет, пиши.

## Telegram-бот

Бот (`bot/`) переписан под настоящий контракт: старая версия ждала другие поля (`results`, `items`, `timestamp`, `terms`) и не запускалась (`handlers/scope` без `.py`). Сервис `bot` в общем compose, токен - в `bot/.env` (образец `bot/.env.example`).

## Авторизация и Telegram (вечер 27.10)

Вход по JWT от бэкендера влит, поверх исправлено:

- CORS не разрешал заголовок `Authorization`: после входа браузер отклонял все запросы.
- Закладки и прогресс вошедшего пользователя хранятся за аккаунтом (`client_id = user:<id>`, `user_id` заполнен), а не за браузером; с токеном `X-Client-Id` не нужен. Значения `X-Client-Id` с префиксом `user:` запрещены, чтобы нельзя было подделать чужой аккаунт.
- Удаление несуществующей закладки - снова `404`, а не `500`.
- Битый или протухший токен даёт `401` на любом пути, кроме выдачи токенов (`register`/`login`/`refresh`/`logout`).
- Регистрация проверяет email, длину имени и пароля и отдаёт ошибки по полям (`email`, `name`, `password`).
- Привязка Telegram (контракт 0.4.0): `POST /auth/telegram/code`, `POST /auth/telegram/link` (только бот), `DELETE /auth/telegram`, поле `telegram` у пользователя. Бот ходит с `X-Bot-Secret` (`BOT_SECRET`) и `X-Telegram-Id`; для привязанного Telegram запрос выполняется от имени пользователя. Миграция `0002_telegram`.

## Личные лекции и курсы (28.10)

- У лекций и курсов есть владелец (`owner`: `user:<id>` или анонимный `X-Client-Id`, миграция `0003_owner`). Списки, поиск, чат, текст, конспект, закладки и прогресс видят только своё и общее (без владельца); чужое - `404`. Править и удалять можно только своё.
- Видео и обложки личной лекции отдаются владельцу или по подписанной ссылке (`?exp=…&sig=…`, HMAC от `JWT_SECRET`, живёт не меньше суток): `<video>` и `<img>` грузят их без заголовков. Ссылки в `playback.url` и `thumbnail_url` уже подписаны. Субтитры - только с токеном или `X-Client-Id` (фронт качает их сам).
- Общие лекции и курсы только для чтения (`403 forbidden`). Поле `mine` у лекции и курса.
- Бот отправляет `X-Client-Id` и Telegram-заголовки на каждом запросе (middleware), а не только для закладок: иначе он не видел бы свои лекции.
- Импорт без токена требует `X-Client-Id`. Курс лекции должен быть видим владельцу (иначе `422`).
- При привязке Telegram анонимные лекции и курсы бота переходят в аккаунт, как и закладки.
